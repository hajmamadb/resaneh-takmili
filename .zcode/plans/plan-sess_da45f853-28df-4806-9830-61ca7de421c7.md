## Context

The 731 cards in `resaname_v2.contents` are currently over-classified as theories. The current `content_type` distribution is: **theory 529 (72.4%)**, model 94, framework 22, hypothesis 18, effect 18, paradigm 4, bias 4, principle 2, concept 2, law 1, approach 1. This is because the original seed script (`gen_ai_seed.py` lines 375-381) had an 11-key Persian→English map with a silent `default='theory'` fallback, so any card with a blank/unknown `card_type` became "theory".

The user has provided a refined **33-type / 6-category taxonomy** and requires that (a) AI analysis identify each card's actual type from this taxonomy, and (b) the database be updated accordingly.

## Plan

### Step 1 — Add `content_type_taxonomy` reference table (schema + seed)

**File: `sql/v2_taxonomy.sql`** (new)

```sql
USE resaname_v2;
CREATE TABLE IF NOT EXISTS content_type_taxonomy (
  category_no   TINYINT     NOT NULL,        -- 1..6
  category_key  VARCHAR(40) NOT NULL,        -- a|b|c|d|e|f
  category_fa   VARCHAR(200) NOT NULL,
  category_en   VARCHAR(200) NOT NULL,
  type_key      VARCHAR(40) NOT NULL,        -- English key (used in contents.content_type)
  type_fa       VARCHAR(200) NOT NULL,        -- Persian label
  type_en       VARCHAR(200) NOT NULL,        -- English label
  sort_order    INT         NOT NULL,
  PRIMARY KEY (type_key),
  KEY idx_taxonomy_category (category_no)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;
```

### Step 2 — Re-classify the 731 cards (batched LLM pass)

**Pattern:** follow the existing `sql/llm/batch_manifest.json` + `summaries_llm_NN.json` pattern.

**File: `sql/classify_cards.py`** (new) — prepares batch input files:
- Reads the 731 cards from `resaname_v2.contents` (source_type='card'), joining to `resaname_h.cards` for the original Persian `card_type`, `category_id`, `paradigm`, `level`, and to `llm/cards_all.json` for `approach`/`core_logic`/`analysis`.
- Writes `sql/llm/classify_batch_manifest.json`: 31 batches × ~24 cards each, each with `file`, `ids[]`, `out` (→ `classify_llm_NN.json`).
- Writes `sql/llm/classify_batch_01.json` … `classify_batch_31.json`: each item has `id`, `source_id` (card-N), `title_fa`, `title_en`, `current_content_type`, `card_type_fa` (original Persian from site), `category_id`, `summary` (first 300 chars), `approach` (first 300 chars), `core_logic` (first 300 chars).

**Then I (the agent) author the classification:** for each batch file, read the 24 items and produce `classify_llm_NN.json` of the form:
```json
{ "card-17": {"type_key": "model", "category_no": 1, "confidence": 0.95, "reason": "..."} , ... }
```
The classification prompt (embedded in my reasoning per batch) uses the 33-type taxonomy as the label set, with the card's title_fa, title_en, summary, approach, core_logic, and original card_type_fa as evidence.

**File: `sql/apply_classification.py`** (new) — merges + persists:
- Reads all `classify_llm_NN.json` → merged dict.
- Validates: every card-1..731 present; type_key in the 33 known keys; confidence in [0,1].
- Emits `sql/classify_cards.sql` (UPDATE statements) OR directly updates `resaname_v2.contents.content_type` for the 731 card rows.
- Reports distribution before/after.

### Step 3 — Update the migration script for reproducibility

**File: `sql/migrate_to_v2.py`** — add a Section 0 at the top: read `sql/llm/classify_merged.json` (if it exists) and apply the classification to the card rows after the initial `contents` insert. This way a fresh `resaname_v2` rebuild from the runbook automatically picks up the refined types. If the file doesn't exist, fall back to the current behavior (content_type from ai_documents).

### Step 4 — Verification

After running, verify:
1. `SELECT c.category_no, c.category_fa, t.type_key, t.type_fa, COUNT(cc.contents_count) FROM content_type_taxonomy c JOIN ... ` — distribution of the 33 types across the 731 cards.
2. Spot-check: pick 5 cards from each of the 6 categories, confirm the assigned type matches the title/summary.
3. Confirm no NULL/missing content_type on any card.
4. Confirm the 59 theorists, 15 theories, 35 works are untouched (still their original content_type).
5. Update `sql/v2_report.md` with a new section "Re-classification of 731 cards" showing the before/after distribution.

~447 of the 731 cards have auto-generated (templated) summaries and NULL country. The classification for these will rely more heavily on `title_fa` + `title_en` + original `card_type_fa` than on the summary text. Confidence for these may be lower; the `confidence` field in the output captures this.
